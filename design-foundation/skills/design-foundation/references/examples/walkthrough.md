# 通用流程走查（不针对特定产品）

这份文档走一遍完整流程，用 `<尖括号>` 表示**需要你按实际项目替换**的内容。
想看具体案例的话，看 [案例：剧院售票小程序](./case-theater-ticketing.md)。

---

## 第 1 步：定平台

**问用户**：做在哪个平台？

| 平台 | 选它如果你… |
|---|---|
| 微信小程序 | 面向国内 C 端、要微信生态（支付/分享/扫码） |
| 支付宝/抖音/飞书/百度/QQ/快手小程序 | 对应生态有明确流量或业务入口 |
| iOS App | 要原生体验、推送、相机、后台 |
| Android App | 安卓用户为主、要上架应用市场 |
| 鸿蒙 HarmonyOS | 华为生态 |
| PC 客户端 | 桌面工具、生产力 |
| H5 | 手机浏览器 / 内嵌 WebView |
| PC 网站 / 管理后台 | 桌面浏览器为主 |
| 平板 | iPad / 安卓平板 |
| 快应用 | 厂商联盟快应用 |

**产出**：平台 + 对应规范文档。

> ⚠️ 平台决定画板基准、导航结构、热区、安全区。

---

## 第 2 步：定技术栈

**根据第 1 步收窄**：

- 平台是**小程序** → 原生小程序 / uni-app x / 经典 uni-app / Taro
- 平台是 **iOS/Android/鸿蒙** → 原生 / React Native / Flutter / uni-app / Taro(RN)
- 平台是 **H5** → 纯 H5 / uni-app / Taro / React / Vue
- 平台是 **PC 网站** → React / Vue / Next.js / Nuxt / Svelte / Angular
- 平台是 **PC 客户端** → Electron / Tauri / Flutter Desktop / 原生

**必须多问的两句**：
1. **如果是 uni-app，是 x 还是经典版？**（基准 390px+px vs 750px+rpx）
2. **项目用了哪个 UI 库？**（决定设计要贴合谁的组件规范）

**产出**：技术栈 + 设计基准 + 单位。

---

## 第 3 步：澄清需求

挑 4–6 个最关键的问题：

1. **产品是做什么的？给谁用？**
2. **核心使用场景？**（碎片化 / 深度 / 高频）
3. **内容从哪来？**（PGC / UGC / 工具生成）
4. **品牌调性或参考对象？**
5. **这次要做哪些页面？优先级？**
6. **有没有既定的品牌色或字体？**

**产出**：需求要点。

---

## 第 4 步：选风格

从 `../styles/_index.md` 列全部 16 个，让用户选（可附一句推荐）。

**产出**：风格卡片 + 色板 + 字体 + 圆角 + 阴影 + 布局规则。

---

## 第 5 步：选架构

从 `../architectures/_index.md` 列全部 4 个（1 是地基，2/3/4 可组合）。

**产出**：架构 + 令牌分层 + 组件分层。

---

## 第 6 步：选字体与图标

- 字体：`../libraries/fonts.md`，**按平台过滤**（小程序只能用系统字体；Web/App 可自定义）
- 图标：`../libraries/icons.md`，**在官网搜一遍你要用的所有图标**

**产出**：字体（含许可确认）+ 图标库。

---

## 第 7 步：产出《设计规范简报》

写入项目 `docs/design-brief.md`，模板见 `../requirements/brief-template.md`。

**必须包含**：
```
产品概述 / 平台规格 / 技术栈规格 / 色彩 / 字阶 / 间距与圆角 / 组件清单 / 页面清单 / 状态清单 / 动效规范 / 参考
```

**这份简报是后续所有设计的唯一真源。**

---

## 第 8 步：质量自检

按 `../quality/review-gate.md` 逐项过：

- 平台规范（画板/导航/热区/安全区）
- WCAG 2.2 AA 对比度
- 状态齐全（hover/focus/disabled/loading/empty/error）
- 令牌一致性
- 反 AI 味

**不过门禁就先改简报，不要开始画。**

---

## 第 9 步：验证 MCP + 确认文件

1. 用 `figwright-mcp` 的 `list_files` 检查连通性
2. **列出文件让用户选**目标 Figma 文件
3. 确认页面命名

**MCP 没通、文件没确认，就不要开始画。**

---

## 第 10 步：MCP 落地

按 `../figma-delivery/` 的规范建页面：

1. `01_Foundation`：色板、字阶、间距
2. `02_Components`：可复用组件
3. `03_Pages`：按页面清单逐页生成

---

## 第 11 步：走查修正

逐项核对简报 vs 实际，列出偏差，回第 10 步修。

---

## 常见问题

**Q：用户说「别问了，直接画」？**
平台、技术栈、MCP 连通性、目标文件**还是要确认**，其它可以跳。

**Q：用户说「风格都不对」？**
按 `../02-how-to-add.md` 去 GitHub 搜新风格。

**Q：一次要做多端？**
一套设计系统 + 各端适配，见 `../cross-platform.md`。

---

## 检查清单（每次交付前）

- [ ] 平台已定 + 规范已读
- [ ] 技术栈已定 + 基准/单位已确认
- [ ] 简报已产出并通过门禁
- [ ] MCP 已连通 + 目标文件已确认
- [ ] Figma 页面命名/结构规范
- [ ] 走查已完成
