# 完整示例：剧院售票小程序首页

**这个例子走通全流程**：需求 → 平台 → 风格 → 架构 → 字体图标 → 简报 → 门禁 → Figma 落地。

> 这是一个真实项目（本会话中已实际生成过），用来演示 skill 的完整用法。

---

## 第 1 步：定平台

**问用户**：做在哪个平台？

**用户答**：微信小程序，面向国内观众买演出票。

**读** `platforms/wechat-miniprogram.md`，得到：

| 项目 | 数值 |
|---|---|
| 画板基准 | 375px（750 交付） |
| 导航栏 | 128rpx |
| TabBar | 98rpx（2–5 项） |
| 胶囊避让 | 高 32pt，iOS 宽 88 / Android 宽 96，距右 10px |
| 字号 | 22 / 17 / 15 / 14 / 12 pt |
| 热区 | 7–9mm（≈44px @2x） |

---

## 第 2 步：定技术栈

**问用户**：用什么实现？原生小程序还是跨端框架？

**用户答**：先用原生小程序开发。

> 💡 **如果用户说用 uni-app，要再问一句是 x 还是经典版**：
> - **uni-app x** → 基准 **390px（1x）**、单位 **px**、导航 44px、TabBar 50px
> - **经典 uni-app** → 基准 **750px**、单位 **rpx**、导航 44px、TabBar 50px
>
> 两者的**导航高度一样**（44px / 50px），但**设计基准和单位完全不同**。用错了，尺寸全错。

**读** `tech-stacks/_index.md`，确认：

| 项目 | 数值 |
|---|---|
| 技术栈 | 原生微信小程序 |
| 设计基准 | 375px |
| 单位 | rpx |
| UI 库 | 自研 / 无 |

## 第 3 步：澄清需求

| 问题 | 回答 |
|---|---|
| 做什么？ | 剧院演出票销售 |
| 给谁用？ | 25–45 岁城市观众 |

## 第 4 步：选风格

**读** `styles/_index.md`，**列出全部 16 个风格**（这里节选 3 个演示）：

| 候选 | 理由 |
|---|---|
| **经典剧院（红金）** | 最贴合「剧院」的文化仪式感，红金有辨识度 |
| 编辑杂志风 | 有叙事感，但偏阅读场景，购票转化弱 |
| 国风宋墨 | 有文化感，但偏文旅，演出票务的「商业感」不足 |

**用户选**：经典剧院（红金）

**读** `styles/classic-theater.md`，带出：
- 主色 `#8C1D18`、强调色 `#C9A227`、背景 `#FAF7F2`
- 中文标题用宋体/衬线，正文无衬线
- 圆角 12px，按钮全圆
- 金只作点缀，不大面积铺

---

## 第 5 步：选架构

**读** `architectures/_index.md`，项目规模：单产品、5+ 页面。

**推荐**：**分层令牌**（地基）+ 组件库（原子设计组织）

**令牌分层**：
```
Primitive:  color/red/600 = #8C1D18
            color/gold/500 = #C9A227
Semantic:   color/brand/primary = alias(color/red/600)
            color/bg/canvas = #FAF7F2
Component:  button/primary/bg = alias(color/brand/primary)
```

---

## 第 6 步：选字体与图标

**读** `libraries/fonts.md`：
- 英文 + 数字：**Inter**（UI 标杆）
- 中文：**思源黑体**（正文）+ **思源宋体**（标题，营造古典感）

**读** `libraries/icons.md`：
- **Lucide**（1500+，中性现代，有 Figma 插件，ISC 许可）

**统一**：24px 栅格，1.8px 线宽，圆头端点。

**读** `quality/review-gate.md`，逐项过：

| 项 | 结果 |
|---|---|
| 画板 375 基准 | ✅ |
| 导航栏 128rpx | ✅ |

| 热区 ≥44px | ✅ |
| 次要文字对比度 | ✅ 4.9:1 |
| 状态齐全 | ✅ 卡片有默认/加载/空态 |
| 颜色来自令牌 | ✅ |
| 无 AI 味 | ✅ 主色是品牌红，不是紫渐变；无 emoji 图标；无三卡片并排 |

**发现的问题**（实际走查时）：
- ❌ 辅助文字原为 `#8A8A8A`（3.5:1 不达标）→ 改为 `#6B6B6B`
- ❌ Tab 未选中色 `#9A9A9A`（2.8:1）→ 改为 `#757575`
- ❌ Banner 底部留白 67px → 高度从 150 收到 120
- ❌ 卡片 2 贴着 TabBar（只隔 2px）→ 调整间距到 66px

**修正后重新过门禁 → 通过。**

## 第 9 步：验证 MCP 连通性 + 确认目标文件

**这一步不做，后面全是白费。**

### 9.1 验证 MCP

用 `figwright-mcp` 的 `list_files` 检查：

- **返回了文件列表** → ✅ MCP 通了
- **返回空数组** → 有插件但没打开文件 → 提示用户打开目标文件并运行 Figwright
- **超时 / 报错** → MCP 没连通 → 提示检查 Figma 桌面端、插件状态，必要时重启

### 9.2 确认目标文件

```
检测到 1 个文件：「剧院售票小程序」
要把设计放到这个文件吗？
页面用新建的「首页」，还是用现有页面？
```

**用户确认后**才进入下一步。

> 💡 **多个文件时一定要列出来让用户选**，不要自己猜。猜错了，设计就画到别的文件里了。

## 这个例子学到的

1. **平台先定** —— 375 基准和胶囊避让，决定了后续所有尺寸
2. **风格给约束** —— 红金配色 + 衬线标题，让「有文化感」变具体
3. **令牌让修改可控** —— 改一处主色，全局生效
4. **门禁挡住真实问题** —— 对比度、间距、AI 味都是自检时发现的
5. **命名让开发能还原** —— `ShowCard/图兰朵` 比 `Group 45` 强一万倍

## 换成别的产品怎么走

**例：知识付费 App（iOS）**
1. 平台 → iOS（390×844pt，44pt 热区，Safe Area）
2. 需求 → 碎片化学习、通勤场景
3. 风格 → 推荐：日系极简（安静）/ 简约浅色（专业）/ 黏土拟态（亲和）
4. 架构 → 分层令牌 + 原子设计
5. 字体 → Inter + 思源黑体；图标 → Lucide
6. 简报 → 按模板写
7. 门禁 → 过
8. 落地 → figwright-mcp

**流程完全一样，只是取值不同。**
