# 需求讨论清单 + 设计规范简报模板

**两个用途**：
1. 前半部分是**提问清单**（澄清需求用）
2. 后半部分是**简报模板**（产出交付物用）

---

# 第一部分：需求讨论清单

**不要一次问完**。挑最影响设计决策的先问，通常 4–6 个。

## 必问（影响设计方向）

| # | 问题 | 为什么重要 |
|---|---|---|
| 1 | **做在哪个平台？** 小程序 / iOS / Android / 网站？ | 决定画板、导航、热区、安全区 |
| 2 | 产品是做什么的？核心功能是什么？ | 决定信息架构 |
| 3 | 目标用户是谁？（年龄/职业/场景） | 决定调性和复杂度 |
| 4 | 这次要做哪些页面？优先级？ | 决定工作量和交付顺序 |
| 5 | 有没有品牌规范或参考对象？ | 决定风格的起点 |
| 5b | **用什么技术栈？** uni-app x / 经典 uni-app / Taro / RN / Flutter / 原生 / H5？ | **决定设计基准、单位、导航高度、可用组件** |

## 选问（影响细节）

| # | 问题 | 什么时候问 |
|---|---|---|
| 6 | 核心使用场景是什么？（碎片化 / 深度 / 高频） | 影响信息密度 |
| 7 | 内容从哪来？（UGC / PGC / 商品 / 工具） | 影响卡片和列表设计 |
| 8 | 需要深色模式吗？ | 影响色彩体系 |
| 9 | 有没有无障碍要求？ | 影响对比度和热区 |
| 10 | 有没有动效预算？ | 影响动效方案 |
| 11 | 竞品或不喜欢的设计？ | 明确边界 |
| 12 | 技术限制？（框架、性能） | 影响实现方式 |
| 13 | 项目用了哪个 UI 库？ | 设计要贴合该库的组件规范 |
| 14 | Figma 目标文件是哪个？ | **落地前必须确认** |

## 怎么问

**不要这样问**（太大）：
- ❌ 「你想要什么风格？」
- ❌ 「有什么要求吗？」

**要这样问**（具体）：
- ✅ 「这个页面用户最主要的一个动作是什么？」
- ✅ 「参考这三个产品，你更喜欢哪个的感觉？为什么？」
- ✅ 「用户是碎片时间用，还是专门坐下来用？」
- ✅ 「首页第一屏必须让用户看到什么？」

## 简报的使用

1. **开工前**：和团队过一遍，确认无误
2. **设计中**：作为唯一真源，所有取值从这里来
3. **交付时**：随设计稿一起交付
4. **迭代时**：改简报，不要直接改设计稿

**简报改了要通知所有人。**
