# 原子设计（Atomic Design）

**调性**：把界面拆成「原子 → 分子 → 有机体 → 模板 → 页面」，自下而上组合。

> 来源：Brad Frost 的 Atomic Design 方法论；工具实现见 `pattern-lab/patternlab`

---

## 五层结构

```
Atoms（原子）
  按钮 / 输入框 / 标签 / 图标 / 文字样式
      ↓
Molecules（分子）
  搜索框（输入框 + 按钮）/ 表单行（标签 + 输入框）/ 列表项
      ↓
Organisms（有机体）
  导航栏 / 卡片列表 / 表单 / 轮播
      ↓
Templates（模板）
  页面骨架（导航 + 内容区 + 侧栏）
      ↓
Pages（页面）
  具体页面实例
```

---

## 每层的判断标准

| 层 | 问题 | 例子 |
|---|---|---|
| **Atom** | 还能再拆吗？不能就是原子 | 按钮、图标、输入框、颜色 |
| **Molecule** | 几个原子拼成的**独立功能单元** | 搜索框 = 输入框 + 搜索图标 + 按钮 |
| **Organism** | 多个分子/原子组成的**界面区块** | 顶部导航、商品卡片、登录表单 |
| **Template** | 页面的**骨架**，内容用占位符 | 列表页模板（导航 + 筛选 + 列表区） |
| **Page** | 填入真实内容的模板实例 | 首页 |

**判断技巧**：如果一个元素**换到别的页面依然成立**，它至少是 Molecule。

---

## 什么时候用

✅ **适合**：
- 组件复用度高（电商、SaaS、内容平台）
- 多页面共享大量组件
- 团队需要明确的组件边界

❌ **不适合**：
- 只有 2–3 个页面的活动页
- 强一次性、强叙事的页面（品牌页、发布会页）
- 设计系统还没稳定时（先做分层令牌）

---

## 与其他架构的关系

- **分层令牌是地基**（原子层的颜色/字体来自令牌）
- 原子设计是**组件层的组织方式**
- 常和**领域分层**结合：Foundation（令牌）+ Patterns（模板）+ Features（领域组件）

```
├── Molecules\     搜索框、表单行、列表项
├── Organisms\     导航栏、卡片、表单
└── Templates\     页面骨架
```

**命名**：`层/名称`，如 `Atoms/Button/Primary`

---

## 反模式

- ❌ **原子层过度拆分**（把图标拆成路径）
- ❌ **分子层过大**（塞了 5 个原子 + 3 个分子）
- ❌ **跨层引用**（原子直接引用有机体）
- ❌ **为了分层而分层**（小项目硬套）
- ❌ **没有文档**（组件什么时候用、什么时候不用）

---

## 检查清单

- [ ] 五层划分清晰，每层有明确标准
- [ ] 组件只引用下一层（不跨层、不反向）
- [ ] 每个组件有用法说明（何时用 / 何时不用）
- [ ] 有组件状态（default / hover / disabled / loading）
- [ ] 原子层来自令牌，不写死值
