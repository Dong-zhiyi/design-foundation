# 领域分层（Foundation / Patterns / Features）

**调性**：按**业务领域**组织设计资产，而不是按视觉层级。适合业务复杂、页面差异大的产品。

> 来源：Brad Frost 的设计系统思想演进 + 业界实践（Booking、Spotify 等）

---

## 三层结构

```
Foundation（基础层）
  令牌、基础组件、设计原则
  —— 跨业务通用
        ↓
Patterns（模式层）
  可复用的界面模式：列表、详情、表单、空状态、导航
  —— 跨业务复用
        ↓
Features（特性层）
  业务专属组件：商品卡片、表单组件、订单流程
  —— 只在特定业务用
```

---

## 各层说明

### Foundation（基础层）

- **令牌**：颜色 / 字体 / 间距 / 圆角 / 阴影 / 动效
- **基础组件**：按钮、输入框、标签、图标、选择器
- **设计原则**：调性、语气、可访问性基线

**特点**：跨业务通用，改动需要严格评审。

### Patterns（模式层）

- **界面模式**：列表页、详情页、表单流、搜索结果、空状态、加载态
- **交互模式**：下拉刷新、上拉加载、分页、筛选
- **布局模式**：分栏、卡片流、网格、时间线

**特点**：**可跨业务复用**，是效率的关键。

### Features（特性层）

- **业务组件**：商品卡片、选择器、支付栏、会员卡
- **业务页面**：下单页、订单确认页、个人中心
- **业务规则**：价格计算、库存展示、限购逻辑

**特点**：**业务专属**，可以有自己的令牌覆写。

---

## 什么时候用

✅ **适合**：
- 业务线多（例如：电商 + 内容 + 会员）
- 页面之间差异大
- 多个团队各自负责不同业务模块

❌ **不适合**：
- 单一业务、页面高度相似
- 小团队（维护三层成本高）

---

## 与原子设计的关系

| 原子设计 | 领域分层 | 说明 |
|---|---|---|
| Atoms | Foundation 的一部分 | 基础组件 |
| Molecules | Foundation / Patterns | 看复用范围 |
| Organisms | Patterns | 可复用区块 |
| Templates | Patterns | 页面骨架 |
| Pages | Features | 业务页面 |

**两者可以叠加**：Foundation 内部用原子设计组织，Features 内部也可以。

## 反模式

- ❌ **把业务组件放进 Foundation**（失去复用性判断）
- ❌ **Pattern 层过薄**（没有真正的复用，只是文件夹）
- ❌ **Feature 层各自造轮子**（同一个列表样式出现 5 个版本）
- ❌ **跨层引用混乱**（Foundation 引用 Feature）

---

## 检查清单

- [ ] 三层职责清晰
- [ ] Foundation 跨业务通用，且有变更评审
- [ ] Patterns 真的被多个业务复用（不是只被一个用）
- [ ] Features 有明确的业务范围
- [ ] 依赖单向向下
- [ ] 每个 Pattern 有用法和禁忌说明
