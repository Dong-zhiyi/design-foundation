# 交付前门禁清单

**不过门禁的稿子不往外发。** 这份清单是设计交付前的最后一道关。

> 来源：综合 `plugin87/ux-ui-agent-skills`（50 道门禁）、`bitjaru/styleseed`（评分-修正闭环）、`zhuyansen/awesome-claude-design-skills` 实测

---

## 门禁规则

- **硬门禁（block）**：不通过**不能交付**，且**不能靠「说明原因」绕过**
- **B 类（重要）**：不通过要说明原因
- **C 类（建议）**：尽量通过

**硬门禁（4 条）**：
1. 对比度：正文 ≥4.5:1，大字号/图标 ≥3:1（**实测**，不是目测）
2. 平台尺寸：画板/导航/热区符合平台规范
3. 令牌：颜色/字号/间距来自令牌，无写死 hex（`token_map` 的 unmapped 为空）
4. 状态：关键组件有 default/disabled/loading 等必要状态

**唯一合法破例方式：waiver。** 写清「哪条规则 + 作用范围 + 理由 + 什么时候过期」，并在交付物里标注。**不许默默破例。**

> 来源：`cgallic/design-os`（rule catalog + block/flag/advise + waivers.yaml）、`Dragoon0x/everything-design-taste`（taste-audit 评分）、`zengwei-code/GameUIAgent`（五维评分）

## A 类：阻断项（必须全过）

### 平台规范
- [ ] 画板尺寸符合平台基准（小程序 375 / iOS 390 / Android 360 / Web 1440）
- [ ] 小程序：导航栏 128rpx、TabBar 98rpx、**胶囊区域已避让**
- [ ] 热区达平台标准（小程序 7–9mm / iOS 44pt / Android 48dp）
- [ ] 状态栏/安全区未被内容遮挡

### 可访问性
- [ ] 正文对比度 ≥4.5:1（实测）
- [ ] 大字号/图标对比度 ≥3:1
- [ ] 状态不只靠颜色区分
- [ ] 焦点态已设计
- [ ] 最小字号 ≥12px

### 完整性
- [ ] 每个交互组件都有 default / hover / active / disabled / loading / empty / error 状态
- [ ] 有明确的空状态（用户第一次使用时看到什么）
- [ ] 有错误状态（网络失败、表单错误）
- [ ] 有加载状态（骨架屏或 loading）

### 一致性
- [ ] 颜色全部来自令牌（没有写死的 hex）
- [ ] 字号来自字阶
- [ ] 间距是 4 的倍数
- [ ] 圆角来自圆角档位
- [ ] 图标来自同一个图标库

### 反 AI 味
- [ ] 主色是品牌色（不是紫渐变）
- [ ] 没有 emoji 当图标
- [ ] 没有「三卡片并排 + 居中」
- [ ] 文案具体（不是空话）

---

## B 类：重要项

### 信息架构
- [ ] 导航清晰，用户知道在哪、能去哪
- [ ] 有返回路径（任何页面都能退出）
- [ ] Tab 数量符合平台规范（小程序 2–5 个）
- [ ] 页面栈深度合理（小程序 ≤10 层）

### 内容
- [ ] 用了真实文案（不是 Lorem ipsum）
- [ ] 考虑了极端数据（空列表、超长文字、大量数据）
- [ ] 图片有 alt 策略
- [ ] 表单有明确的错误提示

### 动效
- [ ] 有 `prefers-reduced-motion` 降级
- [ ] 时长在 100–400ms
- [ ] 没有闪烁 >3 次/秒

### 多端
- [ ] 深色模式已适配
- [ ] 如果要多端，适配规则已明确

---

## C 类：建议项

- [ ] 有微交互反馈
- [ ] 有品牌特有的视觉元素
- [ ] 有「高光时刻」设计
- [ ] 文案有温度（不机械）
- [ ] 有情感化设计（空态插画、成功反馈）

## 修正闭环

门禁不过 → 不要直接重画，而是：

1. **定位问题**：哪一项没过？
2. **回到对应文档**：是平台规范？设计原则？还是风格？
3. **改简报或设计**：改源头，不是改表面
4. **重新过门禁**

**不要**：门禁不过就硬发，然后指望开发/测试发现问题。

## 常见「以为过其实没过」

| 现象 | 问题 |
|---|---|
| 「颜色是品牌色」 | 但辅助色是随意取的 |
| 「有 hover 态」 | 只是变色，没有光标变化 |
| 「有加载态」 | 只有一个转圈，没有骨架屏 |
| 「有错误态」 | 只写了「出错了」，没说怎么办 |
| 「深色模式做了」 | 只是把背景变黑，文字还是深色 |
| 「对比度够」 | 目测的，没实测 |
| 「有焦点态」 | 用的浏览器默认 outline |

## 升级触发器（确认即 HIGH，不受 cap 限制）

以下问题**一旦确认，直接标 HIGH**，不被平均化、不被 cap 截断。清单来自 `jakubkrehel/skills` 的 `better-interface` 升级触发器机制，适配到设计基座场景：

| # | 触发器 | 设计基座中的表现 |
|---|---|---|
| 1 | 交互控件无可访问名称 | 图标按钮没有 `aria-label` 或 tooltip |
| 2 | 键盘可达控件无可见焦点指示 | 焦点态用了 `outline: none` 且无替代 |
| 3 | 指针可达但键盘不可达 | 自定义下拉/弹窗只能鼠标操作 |
| 4 | 动效忽略 `prefers-reduced-motion` | 入场/退场动画没有降级方案 |
| 5 | 320px 宽度或 200% 缩放时内容被裁切 | 窄屏下按钮/文字溢出或重叠 |
| 6 | 正文/控件文字对比度不达标 | 实测 <4.5:1（正文）或 <3:1（大字号/图标） |
| 7 | 状态/含义仅靠颜色传达 | 成功/错误只用颜色区分，无图标或文字 |
| 8 | 破坏性操作无确认/撤销 | 删除按钮直接执行，无二次确认 |
| 9 | 截断内容无查看完整值的方式 | 长文本 `…` 截断后无法展开或 tooltip |
| 10 | 错误信息不说明如何修复 | 只写「出错了」，没有解决方案 |
| 11 | 语义色被误用 | 危险色（红）用于非破坏性操作 |
| 12 | 状态变化仅靠动效传达 | 切换状态时没有颜色/图标/文字残留线索 |

**规则**：触发器确认即 HIGH，列出每一条，不因表面小而降级。cap 可以缩短报告，但绝不能成为 blocker 未报告的理由。

> 来源：`jakubkrehel/skills` → `better-interface` SKILL.md「Escalation triggers」

## 快速自检（30 秒版）

时间紧的时候，至少过这 6 条：

1. [ ] 平台规范（画板/导航/热区/胶囊）
2. [ ] 对比度实测 ≥4.5:1
3. [ ] 状态齐全（loading/empty/error）
4. [ ] 颜色/字号/间距来自令牌
5. [ ] 没有 AI 味三件套（紫渐变/emoji 图标/三卡片）
6. [ ] 有真实文案
7. [ ] **升级触发器**：12 条红线全过（见上方）
