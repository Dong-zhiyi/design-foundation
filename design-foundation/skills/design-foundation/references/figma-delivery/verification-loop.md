# 截图自检闭环

**生成完不算完。** 模型看不到自己画出来的样子，必须截图、让独立裁判打分、修、再截，过线才收工。

> 来源：`model-citizen/design-loop`（独立裁判 + 硬门禁）、`tathagat22/plumb-mcp`（结构 diff + rubric + 视觉评判）、`zengwei-code/GameUIAgent`（VLM 五维评分 + 反思迭代）、`amitpatole/agent-vision`（render→perceive→report→fix）、`codenameakshay/design-compare-mcp`（参考 vs 实现打分）

---

## 为什么必须做

模型画完就说「已生成」，但它**看不见画布**。常见翻车全在截图里才暴露：

- 文字被截断、按钮文字溢出
- 间距出现 13px、17px 这种非 4 倍数的值
- 同一个按钮画了 3 种不同样式
- 颜色写死 hex，没绑变量
- 图层叫 `Frame 234`
- 对比度不够、看不清单词
- 一眼就是 AI 做的

**没有闭环 = 把发现问题的责任推给用户。**

---

## 闭环六步

### 第 1 步：截

对每个页面（每个画板）：

```
get_screenshot(nodeIds: [...])        // 直接看
save_screenshots(nodeIds: [...], outDir: "_work/shots")   // 要存档时
```

**要求**：
- 每个页面至少 1 张全页截图
- 有状态的组件，每个状态各 1 张
- 深色模式单独 1 张

### 第 2 步：判（独立裁判，不要自评）

**铁律：建造它的模型不能给它打分。** 开一个**干净上下文**的子 agent，只给它：
- 截图
- 这份 rubric
- 设计规范简报（用于判断是否符合）

> 本环境有 `visual-judge` 子 agent（专做视觉验收）。没有时用 `Agent` 开一个只读子 agent，明确告诉它「只评判，不改文件、不重新生成」。

**5 维 rubric（每维 1–5 分，总分 10 分制）**：

| 维度 | 看什么 | 5 分 | 1 分 |
|---|---|---|---|
| **构图与层级** | 有没有明确视觉焦点；主次是否分明；间距有没有节奏 | 焦点唯一、节奏有变化 | 平均主义、处处一样 |
| **排版** | 字号字重是否分层；行高是否舒适；有没有孤立词 | 层级清晰、无孤字 | 全一样大、大段文字墙 |
| **色彩与对比度** | 主色是不是品牌色；对比度够不够；有没有写死值 | 品牌色主导、全部 ≥4.5:1 | 紫渐变/teal 默认色、看不清 |
| **视觉身份** | 遮住 logo 能看出是什么产品吗；换个人做会一样吗 | 有品牌特征 | 任何产品都能套 |
| **一致性** | 同组件是否统一；间距/圆角/字号是否成体系 | 完全一致 | 同按钮 3 种样式 |

**硬门禁（block，不过直接不许退出）**：
- 对比度：正文 ≥4.5:1，大字号/图标 ≥3:1
- 平台尺寸：画板/导航/热区符合平台规范
- 令牌：颜色/字号/间距来自令牌，无写死 hex
- 状态：关键组件有 default/disabled/loading 等必要状态

**评分线**：总分 **≥8/10 且硬门禁全过** → 收工。

### 第 3 步：确定性检查（能算的不要靠眼睛）

裁判给的是主观分，这些**客观项**用工具算：

| 检查 | 工具 | 期望 |
|---|---|---|
| 变量映射 | `token_map` | `unmapped` 为空 |
| 现有组件复用 | `get_local_components` + `component_map` | 页面里能用实例的地方用了实例 |
| 默认名 | `search_nodes`（搜 `Frame \d+`、`Group \d+`、`Rectangle \d+`） | 0 个 |
| 自动布局 | `get_design_context` 读 frame 的 layoutMode | 非装饰帧 100% 有 auto layout |
| 对比度 | 读节点 fill/text 色值算 WCAG（可选脚本，见下） | 正文 ≥4.5:1 |
| 间距 | `get_design_context` 读 itemSpacing/padding | 4 的倍数 |

> 可选脚本：参考 `Lumi-node/design-loop-ai` 的确定性指标（伽马校正亮度算 WCAG、布局对称性）。放在项目 `_work/` 或插件外，不随插件分发。

### 第 4 步：修

按裁判的清单修，**先修最难的**，不要挑软的。

- 结构性问题（布局系统错、色板错、字阶错）→ 回第 10 步重画
- 局部问题（某个间距、某个颜色）→ 直接改
- **改完必须重新截图**，不能「我觉得改好了」

### 第 5 步：再截

回到第 1 步。**每一轮都要有截图**。

### 第 6 步：退出条件

| 情况 | 怎么办 |
|---|---|
| 总分 ≥8/10 且硬门禁全过 | 收工，把最新截图给用户看 |
| 总分 ≥8/10 但有硬门禁没过 | 先修门禁，修完**重新打分**（修门禁不能掉总分） |
| 连续 2 轮总分没涨 | **停**。别再做小修小补，找结构性原因（布局系统/色板/字阶/素材质量），做一次**大改** |
| 大改后还是不动 | **停，升级给用户**。不要烧第二轮架构猜测 |
| 达到轮数上限（默认 5 轮） | 停，把当前截图 + 分数 + 剩余问题给用户 |

## 停滞检测（别空转）

三种停滞：

1. **单问题停滞**：同一个问题连续 2 轮出现 → 换方案（改间距 → 改布局结构）
2. ** plateau**：平均分连续 3 轮没涨 → 停
3. **基础设施**：截图失败 / MCP 断 → 重试 1 次，再失败就停下报用户，不要盲目迭代

## 记录模板

每轮记一条，便于看趋势：

```
第 1 轮  构图 3  排版 3  色彩 4  身份 2  一致性 3   → 15/20（换算 7.5/10）
  问题：三个等宽卡片居中；按钮文字「立即体验」；主色是默认蓝
  修：改 Bento Grid；文案改「免费试听一节课」；换品牌色 #8C1D18
第 2 轮  构图 4  排版 4  色彩 5  身份 4  一致性 4   → 21/20 → 收工
```

## 检查清单

- [ ] 每个页面都有截图
- [ ] 截图由**独立裁判**打分（不是模型自评）
- [ ] 硬门禁（对比度/尺寸/令牌/状态）全过
- [ ] 总分 ≥8/10
- [ ] 停滞 2 轮后换结构性方案，不是小修小补
- [ ] 最新截图已给用户看
