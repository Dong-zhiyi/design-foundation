# 多平台适配策略

同一个产品往往要覆盖**小程序 + App + Web**。**不要做三套设计**，做一套设计系统 + 三套平台适配。

---

## 核心思路

```
令牌层（Tokens）       —— 全平台共享，一份源
        ↓
组件层（Components）   —— 按平台分叉（导航/热区/手势不同）
        ↓
模式层（Patterns）     —— 各平台各自实现
```

**一句话**：**令牌共享，组件分叉，模式各自实现。**

---

## 一、共享什么

| 层级 | 共享内容 | 说明 |
|---|---|---|
| **色彩** | 全部 | 品牌色、功能色、中性色完全一致 |
| **字体** | 字体族 + 字阶 | 字号可能因平台微调 |
| **间距** | 4 的倍数档位 | 基本一致 |
| **圆角** | 档位 | 可能因平台微调（小程序常用更小圆角） |
| **图标** | 同一套 | 尺寸档位可能不同 |
| **阴影** | 层级 | 深色下规则不同 |

**做法**：一份 DTCG JSON，导出到各平台。

---

## 二、分叉什么

| 项目 | 小程序 | iOS | Android | Web |
|---|---|---|---|---|
| **画板** | 375px | 390pt | 360dp | 1440px |
| **顶部导航** | 128rpx + 胶囊 | Nav Bar 44pt | Top App Bar 64dp | 自定义 Header |
| **底部导航** | TabBar 98rpx | Tab Bar 49pt | Bottom Nav 80dp | 无 |
| **热区** | 7–9mm | 44pt | 48dp | hover |
| **返回** | 左上角 + 胶囊 | 边缘右滑 | 系统返回键 | 无（靠导航） |
| **手势** | 下拉刷新 | 边缘返回 | 返回手势 | hover |

**做法**：组件层按平台建变体，或分平台组件库。

---

## 三、各平台适配要点

### 3.1 小程序 → App

- 导航栏从 128rpx 改成 44/56pt
- TabBar 从 98rpx 改成 49/80pt
- 去掉胶囊避让
- 热区从 44px 改成 44pt/48dp
- 增加手势返回

### 3.2 移动端 → Web

- 画板从 375 改成 1440
- 导航从顶部小条改成水平导航或侧边栏
- 底部 TabBar 改成顶部导航
- 增加 hover 态
- 内容最大宽度 1200–1280px
- 信息密度可以提升（屏幕大）
- 减少留白（大屏留白过多显空）

### 3.3 App → Web

- 去掉 Safe Area 概念
- 增加响应式断点
- 导航可折叠
- 表格可以展示更多列

---

## 四、响应式策略（Web）

**移动优先**：先设计最小屏，再逐级增强。

| 断点 | 宽度 | 布局 |
|---|---|---|
| base | < 640px | 单列，底部导航 |
| sm | ≥ 640px | 双列 |
| md | ≥ 768px | 侧边栏出现 |
| lg | ≥ 1024px | 12 栏 |
| xl | ≥ 1280px | 内容最大宽生效 |

**不要**：把移动端布局等比放大。

## 五、文件组织

### 方案 A：一个文件多页面（推荐小团队）
```
设计文件.fig
├── 04_Pages/
│   ├── 首页/小程序
│   ├── 首页/iOS
│   └── 首页/Web
```
**优点**：组件复用方便
**缺点**：文件大

### 方案 B：组件库 + 页面文件（推荐）
```
设计系统库.fig（发布为 Team Library）
├── 01_Foundation
└── 02_Components

小程序页面.fig（引用库）
├── 03_Patterns
└── 04_Pages
```
**优点**：组件单点维护
**缺点**：需要版本管理

### 方案 C：按平台拆文件（不推荐）
- 组件同步麻烦，容易版本不一致

## 六、组件分叉策略

**不是每个组件都要分叉。** 判断标准：

| 组件差异大 | 组件差异小 |
|---|---|
| 导航栏（平台专属） | 按钮 |
| 底部标签栏 | 输入框 |
| 选择器（Picker vs Dropdown） | 卡片 |
| 日期选择 | 标签 |
| 弹窗（ActionSheet vs Dialog） | 列表项 |

**做法**：
- 差异大的 → 各平台独立组件
- 差异小的 → 一个组件 + 平台变体

---

## 七、常见问题

| 问题 | 原因 | 解法 |
|---|---|---|
| 三端设计稿完全一样 | 没做适配 | 按平台规范分别出稿 |
| 小程序稿直接放大到 Web | 没考虑响应式 | 按断点重排 |
| 组件库版本不一致 | 多文件各自维护 | 用 Team Library 单点维护 |
| 颜色对不上 | 各平台取色值不同 | 统一用令牌 |
| 开发不知道用哪个组件 | 组件命名混乱 | 命名含平台后缀 |

---

## 八、交付建议

**不要一次性交付三端**。建议顺序：

1. **先主平台**（用户量最大的）
2. **再第二平台**（复用主平台的令牌）
3. **最后补全**

**交付时明确标注**：
- 哪些组件是共享的
- 哪些是平台专属的
- 哪些数值有平台差异

---

## 检查清单

- [ ] 令牌层全平台共享（一份源）
- [ ] 组件层按平台分叉（差异大的独立，差异小的用变体）
- [ ] 模式层各平台实现
- [ ] 每个平台的设计稿符合各自规范
- [ ] Web 有响应式断点
- [ ] 组件库单点维护（Team Library）
- [ ] 交付时标注共享/专属
