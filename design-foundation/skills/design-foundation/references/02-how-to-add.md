# 动态新增 SOP

知识库是**活的**。用户说「加一个 XX 风格 / 平台 / 字体库」时，按这个流程走。

---

## 核心原则

**不要凭印象编造数值。** 每条入库的知识都要能追溯到来源。

---

## 五步流程

### 第 1 步：搜索

**优先 GitHub MCP**（如果已连接）：
```
用 GitHub 搜索：<风格名> / <关键词>
筛选：stars > 500，按最近更新排序
```

**MCP 不可用时**，用 exa 抓取 GitHub 页面：
- 搜索页：`https://github.com/search?q=<关键词>&type=repositories`
- 仓库页：`https://github.com/<owner>/<repo>`

**关键词建议**：
| 要找什么 | 搜索词 |
|---|---|
| 设计风格 | `design style skill`、`ui style`、`<风格名> design` |
| 设计系统 | `design system`、`<公司名> design system` |
| 小程序规范 | `miniprogram design`、`wechat miniprogram ui` |
| 字体 | `<字体名> github`、`open source font` |
| 图标 | `<风格> icons`、`icon library` |

### 第 2 步：筛选

**入库标准**（缺一不可）：

| 条件 | 阈值 | 原因 |
|---|---|---|
| Star 数 | **> 500** | 有一定社区验证 |
| 最近提交 | **近 1 年内** | 避免停更 |
| 许可证 | **明确且允许商用** | 法律风险 |
| 文档质量 | 有 README + 示例 | 能提炼出准确信息 |

**加分项**：
- 有官方 Figma 库 / 插件
- 有设计稿或在线预览
- 被知名产品使用

**一票否决**：
- 许可证不明（如「Other」且无说明）
- 超过 1 年未更新（除非是稳定的规范类）
- 没有 README

### 第 3 步：提炼

**读什么**：
1. README（了解定位和能力）
2. 示例 / 截图（了解实际效果）
3. 配置文件 / tokens（提取准确数值）
4. Issues（了解已知问题）

**写成什么**：
- 风格 → 按 `styles/_template.md` 填卡片
- 平台 → 按 `platforms/` 现有文档结构写
- 架构 → 按 `architectures/` 现有文档结构写
- 字体/图标 → 追加到 `libraries/` 的表格

**必须提取的数值**：
- 颜色：hex 值（不是「深蓝」）
- 尺寸：具体 px/pt/dp（不是「较大」）
- 字体：字族名 + 字号 + 字重
- 圆角/阴影：具体数值

### 第 4 步：落盘

1. **写文件** → 对应目录
2. **更新索引** → `styles/_index.md` 或 `platforms/_index.md` 的表格/速查
3. **更新来源** → `01-sources.md` 加一行（仓库名 + star + 许可 + 用途）
4. **更新复核记录** → `01-sources.md` 的复核表加一行

### 第 5 步：确认

给用户看：
- 新增内容的**摘要**（这是什么、有什么特点）
- **来源**（哪个仓库、star 数、许可）
- **落盘位置**（哪个文件）

用户确认后生效。**不要静默入库。**

## 新增风格示例

用户说：「加一个赛博朋克风格」

```
1. 搜索 → GitHub 搜 "cyberpunk design style"
2. 筛选 → 找到 `cumabozkurt/god-of-design`（含 Cyberpunk 条目，有完整色板）
3. 提炼 → 提取色板、字体、布局规则、反模式
4. 落盘 → styles/cyberpunk-y2k.md
        → 更新 styles/_index.md
        → 更新 01-sources.md
5. 确认 → 给用户看摘要和来源
```

---

## 新增平台示例

用户说：「加一个支付宝小程序平台」

```
1. 搜索 → 找支付宝小程序官方设计规范
2. 筛选 → 确认是官方文档、持续更新
3. 提炼 → 提取画板基准、导航栏高度、组件尺寸、特殊约束
4. 落盘 → platforms/alipay-miniprogram.md
        → 更新 platforms/_index.md 的决策树和对照表
5. 确认
```

## 质量要求

新增内容必须：

- [ ] 有明确来源（仓库/文档链接）
- [ ] 数值具体（可落地，不是形容词）
- [ ] 有适用/不适用场景
- [ ] 有反模式（不要怎么做）
- [ ] 有检查清单
- [ ] 已更新索引和来源表

**宁可少收录，不要收录没来源的内容。**

## 新增图标库 / 字体库（额外核实两项）

图标库和字体库比其他条目多两个硬性条件，**不满足就不收录**：

### 1. 开源 + 可商用

| 接受 | 拒绝 |
|---|---|
| MIT / ISC / Apache-2.0 / OFL / BSD | ❌ NC（非商用）、❌ 专有许可、❌ 许可不明 |
| 要求署名的（CC BY）可以收录，但**必须标注署名要求** | ❌ 只提供「个人免费」的 |

**核实方法**：打开仓库的 `LICENSE` 文件或官网 License 页面，**不要凭印象**。

> ⚠️ **聚合类要特别小心**：像 Iconify 这种聚合器，每个图标集有自己的许可。收录时要写明「各库许可不同，用前查具体库」。

### 2. 支持字体图标（iconfont / webfont）

| 情况 | 处理 |
|---|---|
| ✅ 官方提供字体包 | 直接收录，写明包名和用法 |
| ❌ 只有 SVG / 组件 | 可以收录，但**必须标注「无官方字体包」**，并说明可用 IcoMoon / Fontello / Iconify 转换 |
| ⚠️ 不确定 | **标「待确认」，不要当结论** |

**核实方法**：查仓库的 packages 列表或官网的 Download / Usage 页面，看有没有 font / webfont / iconfont 字样。

### 收录模板（追加到速查表）

```
| 库名 | 数量 | 风格 | 权重/变体 | 许可 | 商用 | 字体图标 | Figma 插件 | 来源 |
```

**示例**：
```
| Tabler Icons | 6200+ | 线性、2px 统一 | 2（outline/filled） | MIT | ✅ | ✅ @tabler/icons-webfont | ✅ | tabler/tabler-icons |
```

## 定期复核

**每季度做一次**（或平台大版本更新时）：

1. 打开 `01-sources.md`
2. 逐个检查仓库是否还在、是否停更
3. 检查 star 数变化
4. 检查许可变更
5. 更新复核记录表

**停更处理**：标注「已停更，仅供历史参考」，不再推荐为新项目首选。
