# 风格库索引

每个风格一张卡片，字段统一。**不要凭印象编数值**——每张卡片都标了来源仓库。

---

## 怎么选风格

1. 先看**平台 + 技术栈**（`../platforms/_index.md`、`../tech-stacks/_index.md`）——某些风格和平台天然不搭
2. 再看**产品调性**——工具类偏理性，内容类偏编辑感，娱乐类偏情绪
3. 最后看**用户**——年龄、文化背景决定接受度

### ⚠️ 必须列全，让用户选

**把全部风格列出来给用户选**，不要只挑 3 个。用户的判断你不该替他做。

- ✅ **列表 + 一句推荐**：「根据你的产品，建议重点看 2、5、9；完整列表如下」
- ❌ **只给 3 个**：用户可能想要的那一个正好没被列出来

**列表格式**（一行一个）：
```
1. 经典剧院（红金）— 庄重有仪式感，适合剧院/文博/高端品牌
2. 现代深色 / Linear — 克制精确，适合开发者工具/数据产品/SaaS
...
```

## ⚠️ 风格选型的常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 风格凌驾于平台规范之上 | 小程序里做了 20px 大圆角，和胶囊打架 | 平台尺寸优先，风格只影响视觉层 |
| 一次混用多种风格 | 界面没有统一语言 | 主风格 1 个，最多 1 个辅助风格 |
| 只看截图不看数值 | 落地时全是「感觉」 | 卡片里必须有具体 hex / px |
| 忽略深色模式 | 深色下文字看不清 | 选风格时就确认深色方案 |
| 强风格 + 长内容 | 可读性崩塌 | 强风格只用于短页面（首页/活动页） |
