# 色彩体系推导指南

**从 1 个品牌色推出完整系统。** AI 生成时需要 success/warning/error/info 四色 + 各状态深浅变化，不能只靠风格卡片的 5-7 个色值。

> 来源：`figma/sds`（Simple Design System 色彩架构）、`luogao/design-atlas`（tokens.css 色彩系统）、`yanliudesign/design-style-skill`（DNA 色彩评分）

---

## 一、色彩层级

```
品牌色（1 个）
  ↓ 推导
主色阶（50–900，9 档）
  ↓ 映射
语义色（success / warning / error / info）
  ↓ 适配
深色模式（Light → Dark 转换规则）
```

---

## 二、从品牌色推导主色阶

**输入**：1 个品牌色（如 `#5E6AD2`）

**输出**：9 档色阶

| 档位 | 用途 | 推导规则 |
|---|---|---|
| 50 | 最浅背景 | 品牌色 HSL，L=95%，S=20% |
| 100 | 浅色背景 | L=90%，S=30% |
| 200 | 边框/分隔 | L=80%，S=40% |
| 300 | 次要元素 | L=70%，S=50% |
| 400 | 次要操作 | L=60%，S=60% |
| 500 | **品牌色原值** | 保持不变 |
| 600 | Hover 状态 | L=45%，S=65% |
| 700 | Active 状态 | L=35%，S=70% |
| 800 | 深色文字 | L=25%，S=75% |
| 900 | 最深文字 | L=15%，S=80% |

**工具**：用 HSL 调整，不要用 RGB 插值（RGB 插值会产生脏色）。

**示例**（品牌色 `#5E6AD2` → HSL `235° 55% 60%`）：

| 档位 | HSL | Hex |
|---|---|---|
| 50 | 235° 20% 95% | `#EEF0FB` |
| 100 | 235° 30% 90% | `#DDE1F7` |
| 200 | 235° 40% 80% | `#BBC3EF` |
| 300 | 235° 50% 70% | `#99A5E7` |
| 400 | 235° 60% 60% | `#7787DF` |
| **500** | **235° 55% 60%** | **`#5E6AD2`** |
| 600 | 235° 65% 45% | `#4A55B8` |
| 700 | 235° 70% 35% | `#3A4299` |
| 800 | 235° 75% 25% | `#2A307A` |
| 900 | 235° 80% 15% | `#1A1E5B` |

## 三、语义色映射

**原则**：语义色不是随便选，要和品牌色协调。

| 语义 | 推荐色相 | 说明 |
|---|---|---|
| **Success** | 绿（120–160°） | 通用；金融可用蓝绿（170°） |
| **Warning** | 黄/橙（35–50°） | 警告；避免纯黄（对比度低） |
| **Error** | 红（0–10°） | 错误/危险；避免过亮 |
| **Info** | 蓝（200–220°） | 信息提示；或用品牌色 |

**推导方法**：同主色阶，用语义色的 HSL 生成 50–900。

**示例**（Success 绿 `#22C55E` → HSL `142° 71% 45%`）：

| 档位 | Hex | 用途 |
|---|---|---|
| 50 | `#F0FDF4` | 成功背景 |
| 100 | `#DCFCE7` | 浅色成功 |
| 500 | `#22C55E` | 成功主色 |
| 600 | `#16A34A` | Hover |
| 700 | `#15803D` | Active |

## 四、深色模式色彩转换

**原则**：深色模式不是简单反色，是重新映射。

| 浅色模式 | 深色模式 | 转换规则 |
|---|---|---|
| 背景 `#FFFFFF` | `#0D0D0F` | 用风格卡片指定的深色背景 |
| 表面 `#F7F7F5` | `#16161A` | 比背景亮 1 档 |
| 描边 `#E5E7EB` | `#2A2A32` | 比表面亮 1 档 |
| 主文字 `#111111` | `#E8E8EC` | 高对比但不纯白 |
| 次要文字 `#6B7280` | `#8A8A96` | 保持对比度 ≥4.5:1 |
| 主色 500 | 主色 400 | 深色模式下主色提亮 1 档 |
| Success 500 | Success 400 | 语义色同理提亮 |

**关键规则**：
- 深色模式下**不用纯黑**（`#000`），用 `#0D0D0F` 或风格指定的深色
- 深色模式下**不用纯白文字**，用 `#E8E8EC`
- 深色模式下**阴影几乎无效**，用描边分层
- 语义色在深色模式下**饱和度降低 10-15%**（避免刺眼）

## 六、语义 Token 分层原则

**核心原则：原语按色相命名，语义按角色命名。** 这是色彩系统可扩展性的关键。

### 三层架构

```
原语层（Primitive）     语义层（Semantic）      组件层（Component）
─────────────────      ──────────────────      ──────────────────
--blue-600          →  --color-accent-solid  →  Button background
--blue-100          →  --color-bg-subtle     →  Card hover
--gray-800          →  --color-text-primary  →  Heading color
--gray-400          →  --color-border        →  Divider
--red-600           →  --color-danger-solid  →  Delete button
```

### 规则

| 规则 | 说明 | 反例 |
|---|---|---|
| **原语只定义值，不直接使用** | `--blue-600` 是值，不是用途 | ❌ 组件里直接写 `var(--blue-600)` |
| **语义 token 指向原语** | `--color-accent-solid` → `--blue-600` | ❌ 语义 token 名叫 `--color-blue-button` |
| **组件只引用语义 token** | Button 用 `--color-accent-solid` | ❌ Button 用 `var(--blue-600)` |
| **一个 token 一个角色** | 分隔线 token 不借给文字用 | ❌ `--color-border` 用在 `color:` 上 |
| **语义名不含色相或组件名** | 叫 `--color-accent-solid`，不叫 `--color-blue-button` | ❌ `--color-sidebar-gray` |
| **品牌色叫 accent，不叫 primary** | `--color-accent-solid` + `--color-text-primary` 共存时，品牌色应叫 accent | ❌ 两者都带 primary 造成混淆 |

### 深色模式下的语义重映射

深色模式**不是**把原语色阶倒过来用，而是**语义 token 指向不同的原语档位**：

| 语义 token | 浅色模式指向 | 深色模式指向 | 原因 |
|---|---|---|---|
| `--color-accent-solid` | `--blue-600` | `--blue-400` | 深色背景上需要更亮的强调色 |
| `--color-bg-surface` | `--gray-50` | `--gray-800` | 表面色在深色模式下变深 |
| `--color-text-primary` | `--gray-900` | `--gray-100` | 文字色反转但不用纯白 |
| `--color-border` | `--gray-200` | `--gray-700` | 边框在深色模式下更淡 |

**关键**：组件代码不关心模式切换，它始终读 `--color-accent-solid`，由主题层决定指向哪个原语。

### 一个视图一个强调操作

当填充色编码主要强调时，**一个视图只有一个主要操作**获得填充色，其他操作保持中性（描边或文字按钮）。

- ✅ 一个页面只有一个「主要按钮」用品牌色填充
- ✅ 多个彩色背景可以共存，前提是它们编码**不同状态或类别**（如标签色），而非竞争为主要操作
- ❌ 同一行里两个按钮都用品牌色填充

> 来源：`jakubkrehel/skills` → `better-colors` SKILL.md「Fill exactly one action per view」

## 七、检查清单

- [ ] 品牌色有完整 50–900 色阶
- [ ] 四语义色（success/warning/error/info）各有 50–900
- [ ] 深色模式有对应映射（不是简单反色）
- [ ] 所有文字对比度 ≥4.5:1（AA）
- [ ] 语义色在深色模式下饱和度降低 10-15%
- [ ] 没有用纯黑（`#000`）或纯白（`#FFF`）作为主色
- [ ] 原语 token 不直接在组件中使用
- [ ] 语义 token 名不含色相或组件名
- [ ] 一个视图只有一个填充色强调操作
- [ ] 深色模式下语义 token 指向不同原语档位（非简单反转）
